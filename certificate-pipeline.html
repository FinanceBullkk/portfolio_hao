01 · The Problem

Fragmented manual work & silent failure risks

Issuing a recurring certificate batch previously required juggling several disconnected tools: designing in Canva, splitting multi-page PDFs through web tools, running local scripts for renaming, uploading files to Google Drive, and triggering a spreadsheet script to send individual emails.

This fragmented process created three critical bottlenecks:

01
Repeated manual handling
Event organisers and L&D coordinators had to split files, verify names, copy Drive links, and handle email attachments by hand.
02
Silent order-shift risk
Relying on file order meant a skipped page or re-sorted row could shift later files without an obvious warning.
03
Developer Dependency & Lack of Visibility
When online splitters crashed or SMTP limits triggered, non-technical coordinators had no visible logs to diagnose errors and required engineering intervention.
02 · Objectives & Constraints

Engineering goals for a dependable certificate studio

To reduce tool switching and make mistakes visible, the system was designed around four practical requirements:

Core Feature
Guided ingestion

Accept a merged PDF and split it without throwing away the original vector text.

Accuracy
Deterministic Matching

Each page reads its own text layer via OCR with full Vietnamese Unicode diacritic support.

Performance
Reviewable workspace

Keep the queue, preview, and review controls together so a coordinator can inspect a batch.

Autonomy
Clear handover

Document the normal path, the dry-run path, and the exception that needs an owner.

1
Pillar 1 · Ingestion & Vector Splitting
Vector PDF splitting with a lightweight preview cache

The backend extracts single-page vector PDFs using pypdf and prepares a lightweight preview with pypdfium2. The original document remains available for export while the queue stays easy to scan.

2
Pillar 2 · OCR Extraction & Sheet Alignment
Vietnamese OCR and Unicode diacritic normalisation

To avoid relying on page order, each page names itself. pdfplumber extracts the printed name and masked certificate code, then normalises Unicode before comparing with the synthetic roster. A mismatch stays visible for human review.

CERTIFICATE TEXT LAYER

Each page names itself from its own text. Diacritics and casing are normalised before comparing (test data).

3
Pillar 3 · UI / UX Architecture
Review workspace and preview lightbox

The queue, certificate preview, and action bar stay together while the list can scroll independently. A lightbox gives the reviewer a closer look before a row moves to dispatch.

4
Pillar 4 · Delivery & Safety Governance
Pre-flight safety audit and controlled dispatch

Before dispatch, a pre-flight safety audit validates recipient syntax and flags missing addresses. Operators can run a simulation (dry run), inspect the queue, and only then use an approved Gmail or Outlook SMTP connection.

04 · Design outcomes

Make the risky handoffs visible

BEFORE — FRAGMENTED SCRIPTS
▪ Several separate tools and repeated file handoffs
▪ Manual splitting, renaming, copying, and sending
▪ Page re-sorting caused silent email mismatches
▪ Required developer setup and terminal commands
AFTER — CERTSTUDIO CLOUD PLATFORM
✦ One guided workspace for intake, review, and dispatch
✦ Page-level matching makes an exception visible before sending
✦ Dry-run and audit outputs support a deliberate handover
✦ Production access remains separated from public proof
01
A shorter, inspectable path
The workflow puts intake, matching, review, and dispatch in one place. Timing claims are intentionally omitted until a baseline and dated sample are approved.
02
A visible safety gate
Each page can be compared with the roster before it enters the dispatch queue. This is a design control; measured error rates require owner evidence.
03
A handover a team can inspect
Dry-run status, held rows, and an exportable audit record make the operating path easier to explain. Team adoption and compliance outcomes remain owner-dependent.
