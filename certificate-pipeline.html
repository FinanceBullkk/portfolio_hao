The problem

A week of manual work, every batch

The L&D team made the certs in Canva. Then someone split the merged PDF one page at a time through a free online splitter, renamed every file by hand, and attached and sent each one individually through Gmail. About 1 to 2 days to make a batch, then 2 to 3 more days renaming and sending it. Slow, easy to get wrong, and it got worse every time training volume grew.

Automated · Python desktop tool · "CLT Certificate Renamer"
Split & rename one click · was file by file

This is the part that makes the whole thing safe. The tool relies on no page order and no mapping file. pdfplumber reads each page's own text and pulls the name and cert ID printed on that certificate. So a re-sorted Sheet or one skipped person cannot shift every file one position over, which is the failure that silently sends 42 people someone else's certificate. pypdf then splits and renames.

Automated · Google Apps Script · the "Cert Sender" menu
Match, test-send & log one run · was 2 to 3 days

Run it from the Cert Sender menu in the Sheet. Before anything sends, every file has to match its Sheet row on two keys, name and cert number, with Vietnamese diacritics and casing normalized first. One key is not enough to be sure. A mismatch gets flagged, never guessed. Then a test send lands in my own inbox, and only after I have read it does the real batch go out.

NGUYEN VAN A (C-COM 26.02-001).pdf name ✓cert no. ✓ 2/2 → send
"Nguyễn Văn A" in the Sheet still matches. Diacritics and casing are normalized before comparing.
TRAN THI B (C-COM 26.02-007).pdf name ✓cert no. ✗ 1/2 → flagged, not sent
Both keys must match or nothing sends, so a cert cannot reach the wrong person.

Why it's solid

Reliability was the feature

01
Every failure is visible
Dry runs, a failed.log and marked sheet rows mean a bad page or an unmatched name never disappears quietly. You see it, and you fix it.
02
Safe to re-run
Idempotency + rate limiting mean you can run it again after a fix without double-emailing anyone or tripping Gmail limits.
03
The team owns it
A GUI, drag-and-drop, a custom Sheet menu, and email previews mean L&D runs the whole thing without a developer.
More automations, same pattern

Two more live Apps Script tools

Same L&D team, same safety-first approach. Both are running day to day, not just the one project this page is built around.

LIVE · GOOGLE APPS SCRIPT
Calendar invite tool

Reads a visual class-timetable grid, taking the date from the column header and the time from the row position, then fuzzy-matches each class to its instructor's email. A "Matched PIC" column lets a human check the guesses before anything sends.

GUARDRAILS
✓ Two-phase flow. Build a review table, a human marks rows ready, then it sends
✓ Flags unmatched instructors instead of guessing
✓ Idempotent. Never resends, and dedupes on its own
✓ Logs a Calendar Event ID per row for traceability
LIVE · GOOGLE APPS SCRIPT
Exam results tool

Takes an already-scored competency matrix (module × level × points) for one exam period and emails each person their own modules, levels, total points and rank. It assembles and sends. It does not grade.

GUARDRAILS
✓ Only sends rows marked ready
✓ No duplicate sends
✓ Logs failures for follow-up
✓ Scoped to a single exam period, not a cross-time history
