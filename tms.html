Pillar 01 · Identity Governance & Security

A sync that never resets a working password

Handles joiners, movers and leavers across around 1,000 staff. Records match on empCode. An existing employee gets their new details written while the password hash is left alone, which is where roughly 90% of IT credential tickets used to come from. A new joiner gets a seed password and mustChangePassword, so the temporary one cannot survive first login.

Under the hood

What makes it more than a booking tool

01
It keeps a learning record, not just bookings
Most booking tools forget the session once it happens. Here every employee's history, hours and credentials land in one profile, which is the data you need before training can be tied to performance reviews.
02
Completion is measured, not judged
Three gates replace the instructor's opinion. Every certificate carries a verification code and an expiry date, and the system warns people before it runs out.
03
The sync cannot lock people out
Matching on empCode lets an update skip password hashing entirely for existing staff, so a routine sync cannot reset a working login. New accounts still get a forced change on first login.
04
The export is treated as untrusted output
Compliance gaps and training hours aggregate live. The HR Excel export escapes any cell starting with =, +, - or @, so a name typed into the system cannot become a formula in someone's spreadsheet.
